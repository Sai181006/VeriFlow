# VeriFlow supervisor walkthrough — 30 October 2026

## What to say first

"VeriFlow is a small compiler for typed CSV pipelines. It tokenizes and parses
a pipeline, checks types and names, lowers it to logical IR, optimizes typed
expressions, and generates stack-machine bytecode. Its research extension
analyzes an explicit lossy schema change, compiles a new-schema input plan,
and preserves or replays the old pipeline's observable result with guards or
selected retained cells."

The generated code is **VM bytecode and new-schema field bindings**, not a
standalone Python program or a textual rewritten `.vfl` file. `run` and the
migration bundle execute the generated plan.

## The three compiler phases to show in the codebase

| Phase | File and entry point | Output to show |
| --- | --- | --- |
| 1. Front end: lexical and syntax analysis | [`lexer.py`](../veriflow/lexer.py) `tokenize` (line 55); [`parser.py`](../veriflow/parser.py) `parse` (line 206); AST nodes in [`ast.py`](../veriflow/ast.py). | Source-positioned tokens and an AST. |
| 2. Analysis and intermediate representation | [`semantics.py`](../veriflow/semantics.py) `analyze` (line 134) resolves and types fields; [`ir.py`](../veriflow/ir.py) `build_plan` (line 104) shows logical steps and postfix expression IR; [`optimizer.py`](../veriflow/optimizer.py) `optimize_checked_program` (line 124) applies safe typed rewrites. | Symbol table, logical plan, and smaller optimized expressions. |
| 3. Code generation and execution | [`vm.py`](../veriflow/vm.py) `compile_expression` (line 40) and `compile_program` (line 60) emit bytecode; `execute_expression` (line 76) interprets it; [`runtime.py`](../veriflow/runtime.py) executes the CSV pipeline. | `LOAD_FIELD`, `PUSH_INT`, `ADD`, comparisons, jumps, and output CSV. |

The schema-migration extension enters through [`evolution.py`](../veriflow/evolution.py)
`compile_evolution` (line 73), [`impact.py`](../veriflow/impact.py)
`analyze_impact` (line 358), [`evolved.py`](../veriflow/evolved.py)
`compile_evolved_pipeline` (line 46), and [`migration.py`](../veriflow/migration.py)
`run_migration` (line 146) / `replay_migration` (line 76). The CLI wiring is in
[`cli.py`](../veriflow/cli.py). `compile-evolved` produces a binding for each
old field the pipeline observes and includes the compiled VM bytecode.

## Five-minute live sequence (PowerShell, from repository root)

This machine's `python` command resolves to 3.11; use the installed 3.12.14
runtime below. On another machine, substitute any Python 3.12+ executable.

```powershell
Set-Location 'C:\Users\Sai\Desktop\veriflow\veriflow'
$py = 'C:\Users\Sai\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $py --version
Get-Content examples/optimization_students.vfl
(& $py -m veriflow tokens examples/optimization_students.vfl | ConvertFrom-Json) |
    Select-Object -First 8 kind,lexeme
$ast = & $py -m veriflow ast examples/optimization_students.vfl | ConvertFrom-Json
$ast.schema.name.value
$ast.pipeline.name.value
$checked = & $py -m veriflow check examples/optimization_students.vfl | ConvertFrom-Json
$checked.symbols | Select-Object name,type
& $py -m veriflow explain examples/optimization_students.vfl
& $py -m veriflow bytecode examples/optimization_students.vfl
& $py optimization_demo.py
```

Point to `let adjusted = (marks + 2 * 3) * 1 + 0` in the source. The optimizer
turns this into `marks + 6`; the demo shows generated bytecode before and
after, **21 versus 13 expression instructions**, and runs the optimized VM.
The output CSV is:

```csv
name,adjusted
Anika,88
"Mira, S",97
```

It writes two rows and filters one. The standalone `optimize` CLI command
shows the older constant-folding pass; use `optimization_demo.py` when showing
all three optimizations and the corresponding executable bytecode.

To demonstrate a compile-time semantic error and safe runtime validation:

```powershell
& $py -m veriflow check examples/invalid_semantic_students.vfl
& $py demo.py all
```

The first command intentionally exits with code 1 and points at `mark` on
line 7: `Unknown field 'mark'; did you mean 'marks'?`. The second intentionally
rejects an integer column containing `forty` and a mark of `140`, publishes
no partial output, then runs the corrected CSV. Its successful output is
`Anika,82` and `"Mira, S",91` (two written, one filtered). These CSV failures
occur during execution; the unknown-field error occurs during semantic checking.

## Two-minute research extension

First show a value-dependent guard on the Iris public data with an injected
decimal-to-integer schema change. This is a controlled synthetic migration,
not an actual Iris schema history:

```powershell
& $py -m veriflow impact-check evaluation/cases/iris.strict.vfl `
    --evolution evaluation/cases/iris.evolution.vfl `
    --input evaluation/data/iris.csv
& $py -m veriflow compile-evolved evaluation/cases/iris.strict.vfl `
    --evolution evaluation/cases/iris.evolution.vfl
$iris = "output/sir-iris-$(Get-Date -Format yyyyMMdd-HHmmss)"
& $py -m veriflow migrate-run evaluation/cases/iris.strict.vfl `
    --evolution evaluation/cases/iris.evolution.vfl `
    --input evaluation/data/iris.csv --bundle $iris
& $py -m veriflow replay-migration --bundle $iris
```

Expected: `impact-check` says **CONDITIONAL**. It gives a `5.7 → 5` witness:
`sepal_length > 5` changes from true to false after truncation. Among 150
well-typed rows, the guard admits 99 and sparse mode retains the old
`sepal_length` for 51; no row is rejected and no replay mismatch is observed.
This demonstrates the compiler-generated binding, migration-time guard, and
saved sidecar together.

Then show the documented [Malaysian Ministry of Health ICU change of 22 July
2021](https://github.com/MoH-Malaysia/covid19-public/commit/4e80229047d796f14c7aac82910a3377277b699f).
The official change renamed `beds_icu` to `bed_icu` and removed `vent_sari`.
Use the two experimental pipelines over the same 7,315 paired rows:

```powershell
& $py -m veriflow impact-check evaluation/real_history/moh_icu_preserved.vfl `
    --evolution evaluation/real_history/moh_icu_evolution.vfl
& $py -m veriflow impact-check evaluation/real_history/moh_icu_recovered.vfl `
    --evolution evaluation/real_history/moh_icu_evolution.vfl
$preserved = "output/sir-moh-preserved-$(Get-Date -Format yyyyMMddHHmmss)"
$recovered = "output/sir-moh-recovered-$(Get-Date -Format yyyyMMddHHmmss)"
& $py -m veriflow migrate-run evaluation/real_history/moh_icu_preserved.vfl `
    --evolution evaluation/real_history/moh_icu_evolution.vfl `
    --input evaluation/real_history/moh_icu_2021_before.csv --bundle $preserved
& $py -m veriflow migrate-run evaluation/real_history/moh_icu_recovered.vfl `
    --evolution evaluation/real_history/moh_icu_evolution.vfl `
    --input evaluation/real_history/moh_icu_2021_before.csv --bundle $recovered
& $py -m veriflow replay-migration --bundle $recovered
Get-Content "$recovered/migrated.csv" -TotalCount 2
Get-Content "$recovered/sidecar.jsonl" -TotalCount 1
```

The preserved pipeline ignores the removed field: **7,315 admitted, zero
retained cells**. The recovered pipeline selects it: **7,315 recovered, one
old cell retained per row, zero mismatches**. Replay yields 4,025 emitted and
3,290 filtered observations in each case. `migrated.csv` has the new
`bed_icu` column and no `vent_sari`; `sidecar.jsonl` contains the removed
value linked by durable row ID. The `impact-check` status for the second
pipeline is `UNKNOWN` because a new-row-only plan cannot reconstruct the
dropped field; migration makes execution possible by retaining it.

For the full study, open [`migration-results.json`](../evaluation/migration-results.json)
or run `& $py -m evaluation.migration_study`. The full test command is
`& $py -m unittest discover -s tests -q` (103 tests passed on 30 October 2026).
The included [manuscript](paper-manuscript-2026-10-28.md) gives the method,
comparisons, and limits.

## Novelty and honest scope

The candidate contribution is the **combination**, within a typed row-pipeline
compiler, of pipeline-specific observable behavior, sufficient value guards,
generated new-schema bindings, selective old-cell retention, and source-free
replay. It is not a claim that compiler phases, ETL repair, provenance, or
query equivalence were invented here.

| Recent work | Its stated focus | VeriFlow's narrower addition or remaining gap |
| --- | --- | --- |
| [Awiti et al. (2025)](https://reference-global.com/article/10.2478/fcds-2025-0006) | Rules to repair extended-relational-algebra ETL processes after source-schema changes. | VeriFlow checks value-dependent preservation of typed row observations and executes a guard/retain/reject choice. No head-to-head implementation comparison is reported. |
| [Kramer et al. (2025)](https://www.vldb.org/2025/Workshops/VLDB-Workshops-2025/QDB/QDB25_4.pdf) | Operator robustness categories, decision tree, and a self-adaptation vision for cleaning pipelines. | VeriFlow supplies an executable, limited row-wise instance with saved replay evidence. It does not cover uncertain changes or their full cleaning-operator set. |
| [Auge and Heuer (2022)](https://arxiv.org/abs/2211.13810) | Provenance-assisted inversion and sufficient reconstructed sub-databases across schema changes. | VeriFlow selects retained cells according to one pipeline's observations and guards. Storing provenance itself is established prior art. |
| [Ortín et al. (2026 preprint)](https://arxiv.org/abs/2604.22415) | U-Schema pivot migration across relational/document models, trace-driven transformation, and query-result equivalence. | VeriFlow targets deliberate information loss in a small CSV DSL and produces per-row guard/retention decisions. The preprint has broader model scope and much larger scale evidence. |
| [EvoSchema (2025)](https://www.vldb.org/pvldb/vol18/p3655-zhang.pdf) | Text-to-SQL robustness benchmark under schema perturbations. | VeriFlow studies an executable pipeline's typed behavior; one real event is far less diverse than a broad benchmark. |

**Assessment:** ready for a supervisor demonstration and as a focused
workshop/systems-demo draft. It is not yet a strong full research-paper
submission. The formal preservation argument needs independent scrutiny,
the real evaluation covers one schema event with researcher-authored
pipelines, and there is no direct rival-system baseline. A venue template,
author affiliation, and external review are still needed. The next research
step is a second independently documented lossy history and, if feasible,
a comparable baseline; adding generic compiler features would not repair
these evidence limits.
